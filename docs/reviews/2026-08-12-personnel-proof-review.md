## 2. What each finding actually costs

**F-01 — the same component, three specifications.** `person-v3` states the rule flatly: "no engine
verdict machinery exists yet, so every verdict slot on this sheet is drawn empty with its gap ID."
`readout-v3` draws the *populated* verdict — "Coach Sample, Analytics · sample 8 games · confidence
high · league percentile vs week baseline — G-02 · 84th percentile" — as the **default** state, and
demotes the empty one to "DEGRADED FORM", then repeats the populated form at all three widths and at
AX5. `week-v3` does the best thing of the three: it draws verdict-backed as "target form once G-02
lands", verdict-pending as "shipping behaviour today", and labels which is which.

The requirement each serves is `04` §4.5's fabrication rule and §4.4's invented-authority rejection.
The player-facing consequence differs per sheet: on `person-v3` they never see a judgement they cannot
audit; on `readout-v3` the first thing they read on the dominant object is an authority the engine
does not own. Delete-test: remove the populated default from `readout-v3` and nothing is lost that
`week-v3` does not already carry better. These are the definitive references and `04` §6.5 says every
§8 screen family is built against them — so this is not a stylistic spread, it is three incompatible
build instructions for one registry entry.

**F-02 — every budget is local, the cap is global.** `table-v3` declares the closed status vocabulary
and enumerates exactly twelve: `cross.case`, `bolt.slash`, `shield.slash`, `exclamationmark.triangle`,
`clock.badge.exclamationmark`, `binoculars`, `hand.raised`, `graduationcap`, `arrow.uturn.left`,
`star`, `checkmark.seal`, `calendar.badge.exclamationmark`. Then:

- `person-v3` adds `arrow.up.right`, `arrow.down.right`, `tag`, `clock` — pricing each as "2 of the
  global ≤12", "1 of the global ≤12", "2 of the global ≤12";
- `week-v3` adds `checkmark.circle.fill`, `figure.run`, `person.fill.checkmark`;
- `broadcast-v3` adds `hand.raised.fill`, `sparkles.tv`;
- `chrome-v3` adds `person.badge.clock`.

Union of status-class symbols across the library: **at least 20 against a cap of 12**, and that is
after excluding control furniture (`chevron.*`, `magnifyingglass`, `pause.fill`, `forward.end.fill`,
`rectangle.3.group`, `line.3.horizontal.decrease`) exactly as `table-v3` excludes it. The most
generous possible reading — fold `.fill` variants into their base, treat `figure.run` and
`sparkles.tv` as diagram furniture — still leaves 16.

Each contract block computes a *local* spend and then asserts *global* compliance. Nothing in the
library, and nothing in `docs/proofs/design-references/README.md`, holds the running total. §4.5 names
vocabulary growth as "the §4.5 leak detector"; the detector is the one thing the library did not build.

**F-03 — three sheets invent colour.** Five sheets contain no hex outside `04` §6.1 plus the synthetic
trio. `broadcast-v3` adds thirteen, `person-v3` eight, `chrome-v3` six. Most are gallery chrome —
card borders, note grounds — and §4.4 does permit prototype truth in "gallery chrome outside the
native device frame", so the bulk of this is a disclosure failure rather than a token failure:
`tokens-v3` discloses its one deviation ("This sheet's own hairlines are solid canon surface values …
a rendering choice, since canon names no hairline token"); `broadcast-v3`, `person-v3` and `chrome-v3`
disclose nothing.

One instance is not chrome. `broadcast-v3:596–598` draws the turf mow pattern with `#1A452F` (dark)
and `#D2E0D6` (light) — **a second field.turf tone that canon does not hold**, inside the device
frame, on the game's most identity-bearing surface. §6.5's rule is unambiguous: a value appearing only
in a sheet has not shipped.

**F-04 — an unverified number wearing a verified costume.** `tokens-v3` publishes the Q5 Dynamic Type
series for exactly five mapped styles: Title 3 → 55, Headline → 53, Subhead → 49, Footnote → 44,
Caption 1 → 43. `person-v3` and `readout-v3` both cite a sixth endpoint, `caption 2 (11 pt) → 40 pt`,
and `person-v3` routes all custom 10 pt micro-type to it as "the nearest **verified** row". It is not
in the verified table. This is the exact failure `D12` warns about — building an accessibility
contract on unverified guidance — reproduced at the level of a single number, and it is the single
most characteristic slop signature in the set: a plausible figure sitting in a row of sourced ones,
inheriting their authority.

**F-05 — one library, two authoring hands.** `person-v3` renders its gallery chrome white (`#FFFFFF`
ground, `#15171C` ink) while the other seven render DESK dark. It carries no `.card`, no `.vo` — it
uses `.contract-block` and `.notice` instead — so it is the one sheet a tool sweeping the library
cannot read uniformly. The requirement this violates is not a token rule; it is what a *reference
library* is for. Comparing the person components against the table components now means comparing
across two different presentation worlds, and the difference is a generation artefact, not a decision.

**F-06 — the name is doing no work.** Player Fourteen is a QB (OVR 84, No. 14) on `tokens-v3`, a left
tackle (OVR 88, No. 72, age 23, senior) on `table-v3`, a 20-year-old linebacker at Example State
Institute on `person-v3`, and a wide receiver (No. 14, home) on `broadcast-v3`. The defence — "all
identities are mechanical placeholders" — is stated on every sheet and is genuine. But then the name
is carrying nothing a bare token wouldn't, while *looking* like a persistent identity, and the library
loses the one thing it is uniquely placed to prove: that a single player reads coherently across
roster, dossier and match. That coherence is `04b` dimension 4, and the reference set cannot
demonstrate it.

**F-07 — a contract block that does not match its own drawing.** ColumnSet's Overview set draws
`Slot · OVR · Fit · Value` and its Contract set draws `Salary · Yrs · Gtd · Expires` — four fact
columns each beside identity. The card's density-budget line claims five, and §4.5's band is six to
nine. The count is mechanically checkable and it is wrong, which matters more than the miss itself:
it demonstrates that the contract blocks are **self-reported rather than measured**. See §5.

**F-08 — disabled is being drawn as data-absent.** Row `51 Player Six` carries `shield.slash`
(suspended this game) and blanks Slot, OVR and Fit. Suspension does not erase a rating. Two cards
later the same sheet builds its whole scouting-fog card on F21 — "fog is per-fact, not per-player" —
and here a per-player *state* has silently eaten three per-fact values. The player-facing cost is
real: a coach deciding who replaces a suspended starter cannot see the suspended starter's rating.

**F-09 — magnitude in a status colour.** The FormLine rating thread encodes a 40–99 per-game rating in
`state.info` bars. `04` §6.1 defines the `state.*` family as "semantic state; never colour alone" —
a rating is not a state. `dataviz`'s rule is the sharper statement of the same thing: status colours
are reserved and never take a non-status job, because once `state.info` means "magnitude here" it
cannot reliably mean "informational state" anywhere else. Mitigated but not cured by the printed
number beside each bar.

**F-10 — figures reused as set dressing.** `213` and `267` belong to Sample Beta and Sample Gamma on
the OpposedBar card; in the composition immediately below, the same two numbers belong to Sample Alpha
and Sample Beta, across all three widths and the AX5 rendition. Either instance alone is fine; both in
one sheet mean the numbers were placed for shape rather than derived. The card's own VoiceOver
sentence, "Sample Gamma leads by 54", is now wrong for the composition and is not restated.

**F-11 — exact numbers for estimates.** "Next season, projected $12,300,000 over" and "Two seasons
out, projected $3,100,000 under" print to the dollar. §4.2: "Show exact numbers only where the
simulation owns exact numbers. Use bands for estimates." A two-season cap projection is an estimate by
construction, and the sheet's own honesty note concedes the projection computation is unbuilt
G-02-class work. The rest of that ledger is exemplary — the components sum exactly to the committed
total, 101.8% and $4,597,200 over are both arithmetically correct — which is why the two projection
rows stand out as the only unearned figures on the card.

**F-12 — the appearance axis spent on a state.** Dark draws "Inspect evidence — three recorded
plays"; light draws "Inspect evidence — unavailable, disabled state". Economical, and it does surface
the disabled treatment. But the contract point reads "Both appearances, ratios stated: dark and light
rendered", and what is rendered is state A in dark and state B in light — so disabled-in-dark and
enabled-in-light are both undrawn. `CLAUDE.md`'s coverage-boundary rule is the governing principle:
the axis a card claims to cover must be covered by construction, not sampled.

**F-13 — confidence has only two values in practice.** Every populated verdict in the library reads
"sample 8 games · confidence high". Registry 12 defines banded / unknown / observation-count, and
`person-v3` renders all of those *for facts*. No sheet renders a **verdict** at low confidence or on a
thin sample — the states drawn are perfect or absent. That is the state production will build, and it
is the state that makes a simulation feel honest under uncertainty, which `01` §7.2 identifies as the
affect a fictional league has to manufacture rather than inherit.

**F-14 / F-15** are minor and self-explanatory in the table.

## 5. Cross-cutting — what no single proof reveals

**Every budget is priced locally; every cap in `04` §4.5 is global.** This is the same missing decision
eight times, and F-02 is only its most measurable instance. §4.5 caps the symbol vocabulary at twelve
*across the whole product*, secondary regions at two *per screen*, verdict lines at one *per readout*.
Each sheet computes its own spend honestly and then writes "of the global ≤12" as though the global
figure were known to it. It is not knowable to any one sheet, and the library has no place that holds
it. The result is a set that is individually rigorous and collectively over budget. Whatever closes
this — a shared vocabulary table in `04` §6.5, a contract test under G-08 — has to live outside the
sheets, because the defect is structural to per-sheet self-reporting.

**Verification was replaced by transcription, deliberately, and the trade is visible.** The card
contract in `docs/briefs/2026-08-12-reference-library-plan.md` §4 asks that ratios be recomputed at
authoring time; `readout-v3`'s honesty note 3 records that the commissioning instruction overrode this
with quote-from-canon-only. The upside is real and I confirmed it — zero transcription errors in ~7,100
lines. The cost is that the contract blocks lost their only independent check, and the failures that
remain are exactly the ones transcription cannot catch: a self-reported column count that does not
match the drawing (F-07), a verified-sizes table that grew an unverified sixth row (F-04), a glyph
budget that only sums across files (F-02). Where a contract claim is mechanically checkable, it should
be mechanically checked; where it is not, it is an assertion wearing a contract's clothes.

**The library has no shared world.** Eight sheets, five disjoint identity corpora — `Sample
Alpha/Beta/Gamma` on `readout`, `Example State/Coastal/Union` on `table`, `Opponent One–Five` on
`person`, `Home/Away Sample` on `broadcast` — and one name meaning four different players (F-06).
`04` §10 requires the three interactive proofs to depict one continuous fictional save; the reference
sheets were not held to that and it shows. The cost is not aesthetic. `04b` dimension 4 is "world
identity and continuity", and the reference library — the thing every §8 screen family is built
against — is the one artefact that could have proven a player, a team and a week read coherently
across the registry. It currently proves the opposite.

**No sheet was written knowing what the others decided.** F-01 (three verdict rules), F-03 (three
sheets inventing colour where five did not), F-05 (one sheet in a different chrome and class
vocabulary) are all the same underlying fact from different angles: these were authored in parallel
against a shared brief, and no pass afterwards reconciled them. That is precisely the failure mode the
brief anticipates — competent-looking surface standing in for an absent decision — except the absent
decision here is not inside any one sheet. It is the decision to make them one library, which was
declared in `04` §6.5 and `DOC-MANIFEST.md` §4a but never performed.

**What the set gets right, stated so the findings are not read as a verdict on the whole.** The
football is real and specific: twelve status chips that each name the decision they change, per-fact
scouting fog with the scout action sitting in the cell where the answer would be, a market cell that
can answer "Not for sale", an over-capacity meter that draws past its own cap mark at the true
fraction, a call-in that states cost and consequence per path. None of that could be renamed into a
CRM. §4.4's rejection conditions are not met by any of the eight. The defects above are the defects of
work that is nearly right, and every one of them is a data, disclosure or reconciliation edit — not a
redesign.
