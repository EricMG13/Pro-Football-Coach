PRO FOOTBALL COACH · DESIGN REFERENCE v2 · GROUP: FAILURE
Refusals, errors and empty
ErrorBanner and EmptyState have been in the §3 registry since it was written and have never been drawn in any pass. That is not a cosmetic gap: 04 §6 makes "every error path terminates in a presented surface" a contract test, and AUDIT.md:20 records the prior build capturing save and load failures into AppState.lastError and showing the user nothing. The one component that exists to prevent a repeat is the one nobody drew.
REAL marks a state whose trigger already exists in the shipped engine. GUIDE marks one whose trigger is a later phase, drawn so the surface exists before the mechanism does.
1  The rule every one of these obeys
WRONG — AND THE PRIOR BUILD SHIPPED IT
⚠
Cannot do that
Something went wrong. Please try again.
Names no door. The player learns that the app has moods. Two sentences and neither is information.
RIGHT — 04 §7, THE DOOR THAT SHUT
▼
Roster is full at 105
Cut or redshirt one player to sign Okonkwo-Vance.
Names the limit, the number, and the one action that clears it. A refusal is a navigation opportunity — it knows where the fix is, so it offers to go there.
Three parts, always, in this order: the limit that was hit, stated with its number · what would clear it · the control that goes there. Any refusal missing the third part is asking the player to go and find the fix themselves, which is how a refusal becomes a dead end.

3  The save
REAL
the failure the prior build swallowed
SAVE FAILED — BLOCKING, BECAUSE PROGRESS IS AT RISK
▼The season could not be saved
There is not enough space on this iPhone. Your last save was week 8, about 20 minutes ago.
Free up around 30 MB and try again. Nothing is lost while this screen is open.
Three facts the prior build gave none of: what failed, when the last good save was, and what would fix it. "Nothing is lost while this screen is open" is the sentence that stops a player force-quitting and losing the season — the failure mode the message exists to prevent.
SAVE UNREADABLE — VERSION AHEAD
This save was made by a newer version
Save format 7, this build reads up to 5. Update the app to open it. It has not been changed.
P0 built the envelope so the version is readable from a 16-byte header without a full parse — which is exactly what lets this screen state both numbers instead of saying the file is corrupt. A designed capability, finally spent.
SAVE CORRUPT — THE ONLY UNRECOVERABLE ONE
This save cannot be read
The file is damaged past repair. Starting a new career is the only way forward, and it will replace this one.
Says the unsayable plainly rather than offering a "repair" that does nothing. One save means there is no fallback slot, so this screen is the end of a career — and it should read like it, not like a dialog.
4  Empty is a state with a verdict, not an absence
04 §4 — every READOUT states its own verdict, and zero is a readout
INBOX, NOTHING ARRIVED REAL
A quiet week
Nobody needs an answer. Set the plan and play the game.
This one is dangerous and the copy is doing safety work. 04 §1.5 says the game initiates and something arrives every week — 01-RESEARCH.md §6.0 found zero inbound events in the prior build. So an empty inbox is either a real quiet week or the event system has failed, and the player cannot tell. The copy names it as deliberate and points at the next action.
SHORTLIST, NOTHING ON IT GUIDE
No recruits shortlisted
You have 40 contacts left this week and 12 weeks to spend them.
Empty states carry the cost of staying empty. A contact budget that expires is the reason to act, so the number goes in the empty state rather than being discovered later.
RECORD BOOK, YEAR ONE GUIDE
Nothing here yet
Your first season is week 9 of 17. The book fills at the end of it.
The one empty state that is correct and permanent for a while. It says when it will stop being empty, so the player does not read it as broken and does not come back to check.

the state the critique said would actually break
SAVE FAILED AT AX5 · THE LONGEST COPY IN THE PRODUCT
9:4186%
▼Could not save
Not enough space. Last save was week 8.
It broke, and the copy is the fix
At AX5 the full message — three sentences plus a reassurance — needs 612 pt in a 347 pt box. Stated reduction: the headline shortens to "Could not save", the diagnosis keeps only the cause and the last-save week, and the sentence "Nothing is lost while this screen is open" is dropped — because at this size the two buttons say it more clearly than the sentence did.
No bar here, deliberately
A blocking failure hides the destination bar: navigating away is not one of the choices, and 44 pt of chrome offering it would be a lie. 347 pt, not 303.
The rule this yields
Error copy is written twice — a full form and an AX5 form — and the AX5 form is authored, not truncated. A clipped error is worse than a short one.
NOW IN 04 — WRITTEN, NOT PROPOSED
Refusals are enumerable by construction
RosterLegality.Violation has four cases in shipped code. ErrorSurfaceTest should enumerate the enum and assert a banner exists per case, so P7's and P8's new violations fail on the day they are added.
A refusal has three parts
§7 says a refusal names the door that shut. It should also say: and offers the control that opens it. Without the third part a refusal is a dead end that happens to be polite.
An empty inbox is ambiguous by design
§1.5 promises something every week, so emptiness reads as breakage. Either the copy disambiguates, as here, or the inbox is never allowed to be empty — a §1.5 question, not a component one.
